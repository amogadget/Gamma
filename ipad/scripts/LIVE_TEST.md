# Opt-in real backend integration

This test runs real Gamma HTTP endpoints with PencilKit archives generated by an Apple simulator. It does not use a production account/data directory or weaken the production client's HTTPS rules.

1. Repository root on Linux: `backend/venv/bin/python ipad/scripts/live-test-server.py` (foreground, stop after test). This imports the backend test bootstrap, creating a disposable GAMMA_DATA_DIR and account.
2. Forward only Mac loopback: `ssh -N -o ExitOnForwardFailure=yes -R 127.0.0.1:19091:127.0.0.1:19091 mymac`.
3. Sync current ipad sources, generate the Xcode project using the Mac's signing overlay if present, then run:

```sh
xcodebuild -project GammaIPad.xcodeproj -scheme GammaIPad \
  -destination 'platform=iOS Simulator,id=YOUR-IPAD-SIMULATOR-UDID' \
  -only-testing:GammaIPadTests/GammaLiveTests \
  'SWIFT_ACTIVE_COMPILATION_CONDITIONS=DEBUG GAMMA_LIVE_TEST' \
  CODE_SIGNING_ALLOWED=NO test
```

The test-only URLProtocol forwards `gamma-integration.invalid` into that loopback service. Responses, authentication, storage and block logic come from the actual backend, not mocks. TLS certificate policy, public deployment, app UI gestures, process-relaunch outbox scheduling and physical Pencil behavior are outside this test's claims. Without the opt-in flag, the test is skipped. Stop both tunnel and disposable server afterward.
